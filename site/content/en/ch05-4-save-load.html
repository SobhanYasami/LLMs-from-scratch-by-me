Aim. Save a trained model so it does not have to be trained again, and save the optimizer too so training can resume exactly where it stopped.

Training is the expensive part. You want to do it once, store the result, and load it whenever you need the model. A trained model is just its weights: a long list of numbers. Saving it means writing those numbers to a file.

What goes into the file

The book uses torch.save(model.state_dict(), "model.pth"). Our five languages must read each other's files, so we use one plain format:

PartContent
magic8 bytes: LLMCKPT1
settings7 numbers (32-bit integers): vocabulary, context length, embedding size, heads, layers, qkv bias (0/1), has optimizer (0/1)
weightsevery tensor of the model as raw 32-bit floats, in one fixed order (token embedding, position embedding, then each block, the final norm, the output head)
optimizer (optional)the step count, then the two running averages of AdamW for every tensor

That is all. A 3.2 million parameter model plus its optimizer state is exactly 38,906,920 bytes: a 36 byte header (8 magic + 28 settings), 3,242,240 weights, a 4 byte step counter, and two more copies of the weights for the optimizer, at 4 bytes per number.

Why save the optimizer

AdamW remembers, for every weight, two running averages (5.2). If you save only the weights and restart, the optimizer starts from nothing: its first steps are wrong and training can wobble or even throw away progress. To resume training, save and reload the optimizer state as well.

Proof that resuming is exact

The demo saves the trained model and optimizer, loads them into a brand-new model (built from the file's settings), and checks two things:

saved model and optimizer state: 38,906,920 bytes
largest logit difference between the two models: 0.000000
3 more steps, continued: losses [5.898, 6.165, 6.076]
3 more steps, restored : losses [5.898, 6.165, 6.076]
same losses: true
  • The loaded model gives exactly the same scores as the original.
  • Training 3 more steps from the loaded model and optimizer gives exactly the same losses as simply continuing. Nothing was lost in the file.

Files travel between languages

Because the format is plain, a checkpoint written by one language loads in any other. We checked it: Go, Rust, C and Zig, each trained on its own, write byte-identical files (same checksum). Python's file has slightly different weights (the torch rounding of 5.2) but loads in Rust and gives the same scores as Python itself. Run the chapter in two languages and load one's file in the other as an exercise.

The numbers are written as your machine stores them, which is little-endian on every x86 and ARM computer. The files are ignored by git (assets/checkpoints/).

Exercises

  1. Exercise 5.4: in a new session, load the checkpoint and train one more epoch. Does the loss keep falling?
  2. Load a checkpoint without the optimizer and train. How do the first losses compare with a proper resume?
  3. How many bytes would a checkpoint of GPT-2 small (163,009,536 parameters) take, with and without the optimizer?
Answers1) It keeps falling on the training data; watch the validation loss for overfitting. 2) The first steps are larger and noisier because the averages restart at zero (the bias correction compensates a little, but not fully). 3) Without: 163,009,536 x 4 + 36 = 652,038,180 bytes (620 MB); with: three times the weights, 1,956,114,472 bytes (about 1.8 GB).
