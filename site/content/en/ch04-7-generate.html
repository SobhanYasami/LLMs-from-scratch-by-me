Aim. Turn the model's scores into text: pick the next token, append it, and repeat. See why an untrained model produces gibberish.

One token at a time

A GPT never writes a sentence in one go. It predicts one token, adds it to the input, and runs again. The sentence grows by one token per round.

The four steps inside the loop

  1. Crop the tokens to the last context_size (the model cannot look further back than its context length).
  2. Forward pass to get logits [tokens, vocab].
  3. Take the last row. Only the last position predicts what comes next; the earlier rows predict tokens we already have.
  4. Pick the entry with the highest score and append its ID.
Softmax is optional here. The book first turns the scores into probabilities with softmax, then takes the largest. Softmax keeps the order of the numbers, so the largest score is the largest probability: argmax of the logits gives the same token. The Python version keeps the softmax so you can see the probabilities; the others skip it. Always picking the most likely token is called greedy decoding. Chapter 5 adds randomness (temperature, top-k) for more varied text.

(gibberish: the weights are random, nothing has been trained yet)
  • The prompt "Hello, I am" is four token IDs. Six rounds append six more: output length 10.
  • The words that follow are nonsense, and that is the point of the chapter. The model has the right structure, but its weights are random, so its scores carry no knowledge of language. Training (chapter 5) is what turns this skeleton into a model that writes coherently.
  • The text is the same in all five languages, because they build the same model and take the same argmax.

The real 124M model

The same code runs the full GPT-2 small. With random weights it is just as unhelpful, here it starts repeating tokens:

It needs about 1 GB of memory and roughly 10 to 30 seconds (build in release mode: cargo run --release, zig build run -Doptimize=ReleaseFast). Commands are on page 4.1.

Why it is slow-ish. Every round recomputes the whole input from scratch, although the earlier tokens did not change. Real systems cache the keys and values of past tokens (a KV cache) so each round only processes the new token. Raschka's repo has this as a bonus: ch04/03_kv-cache.

Exercises

  1. Generate 20 tokens instead of 6. Does the output ever repeat? Why can a greedy model get stuck in a loop?
  2. Print the top 3 token IDs and their scores for the last position at each round. How close is the winner to the runner-up for the untrained model?
  3. Make the context size 5 (smaller than the text): what does the crop step do once the text is longer?
Answers1) Often yes: greedy always takes the same token for the same context, and once the context repeats, the output repeats. 2) For an untrained model the scores are within a hair of each other; for a trained one the top token usually stands out. 3) The model sees only the last 5 tokens; older ones are forgotten.

Chapter summary

  • Layer normalization keeps each token's numbers at mean 0 and variance 1.
  • Shortcut connections keep gradients alive in deep stacks.
  • A transformer block is attention plus feed forward (GELU), each normalized first and wrapped in a shortcut.
  • A GPT is embeddings, N blocks, a final norm and an output head; size is set by configuration alone.
  • Generation predicts one token, appends it, repeats. Untrained weights give gibberish: next, chapter 5 trains the model.
