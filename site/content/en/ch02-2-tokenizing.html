Aim. A model cannot read text, only numbers. Before numbering anything, cut the text into pieces called tokens.

A token here is a word or a punctuation mark. A regular expression finds the delimiters (punctuation, --, whitespace), and we keep the delimiters so punctuation becomes its own token. Whitespace pieces are then dropped.

"Hello, world!"  ->  ['Hello', ',', 'world', '!']

How the book gets there

  1. Split on whitespace only: re.split(r'(\s)', text) leaves punctuation glued to words ('Hello,').
  2. Also split on , and .: now punctuation is separate, but empty strings and spaces remain.
  3. Filter with item.strip() to drop whitespace pieces.
  4. Add ? " ( ) _ ! and --. Result on the whole story: 4,649 tokens.
In Python, re.split keeps delimiters only when the pattern is in parentheses (a capture group). Go and Rust have no such feature, so they walk the matches by hand. C and Zig have no regex at all, so they scan byte by byte. Same result, more visible mechanism.
We do not lowercase: capitalisation helps a model tell names from common nouns and learn sentence structure. We drop whitespace for brevity; for code (where indentation matters) you would keep it.

Detokenize is lossy

Decoding joins tokens with spaces, then removes the space before punctuation. Original spacing is not stored, so detokenize(split(text)) only round-trips for simple text.
