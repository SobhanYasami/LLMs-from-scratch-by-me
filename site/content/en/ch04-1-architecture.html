Aim. See the whole GPT model as one short pipeline, and know what goes in and what comes out, before we build any piece of it.

A GPT looks big, but it is a short recipe with one part repeated many times. Chapters 2 and 3 gave us the first and the most important ingredients: token embeddings and multi-head attention. This chapter adds the rest and assembles them into a model that turns token IDs into scores for the next token.

The pipeline

Token IDs[T] integers
→
Embeddingstoken + position, [T, D]
→
Transformer blockrepeated N times, [T, D]
→
Final layer norm[T, D]
→
Output head[T, vocab]

T is the number of tokens, D the vector size per token. Everything between the embeddings and the output head keeps the shape [T, D], which is why the block can be stacked as often as we like.

What goes in, what comes out

batch of token IDs, shape (2, 4): [[6109, 3626, 6100, 345], [6109, 1110, 6622, 257]]
logits shape: (2, 4, 50257)  <- [batch, tokens, vocab_size]
  • The two rows are the texts "Every effort moves you" and "Every day holds a", already cut into four token IDs each by the tokenizer from chapter 2.
  • The output has one row of 50,257 numbers for every input token. Entry i of a row is the model's score for "the next token is token i". Those scores are called logits.
  • For generating text we only need the last row of each sequence: it says what comes after the whole input. Section 4.7 does exactly that.

The model is untrained

All weights start as small random numbers, so the scores mean nothing yet. Every language here draws them from the same seeded generator (Normal with spread 0.02, biases 0, layer-norm scale 1 and shift 0), in a fixed order, so all five languages build exactly the same model and print the same numbers. They differ from the book's torch numbers, but the shapes and sizes are identical. Chapter 5 trains the model.

Code: the model (this page shows the assembled GPT)

Read it top to bottom now to see the shape of the whole; the next pages build each ingredient it uses (LayerNorm, TransformerBlock, ...).

Python uses torch modules, so batches are built in. Go, Rust, C and Zig have no tensor library: a sequence is one Matrix [T, D] and the demo loops over the batch. The math per sequence is identical.

Check yourself

Why can the transformer block be repeated 12 times?Its output has the same shape as its input, [T, D], so one block's output can be the next block's input.
What is the shape of the logits for a batch of 2 texts with 4 tokens each?[2, 4, 50257]: one score per vocabulary entry for every token.
Why does the untrained model print the same numbers on every run?The weights come from a seeded random generator, so the "random" model is identical each time.
