The site is built with Hugo. A new page is one file; a new chapter is a few lines of data. Navigation, roadmap, progress bars, chapter pages and the code tabs are generated from that.

The pieces

Everything lives in site/:

WhereWhat it holds
site/content/en/*.htmlOne file per page: a front-matter block, then HTML. The home page is _index.html.
site/content/fa/*.htmlPersian translations, one file per English page, same file name.
site/data/chapters.yamlThe whole book: chapters, sections (English and Persian titles), and which languages implement each chapter.
site/data/roadmap.yamlThe global map on the Roadmap page: the three stages, their steps and the "inside the model" boxes. A box is solid when the page it names exists, dashed until then. To light one up, write its page and use that file name here.
site/data/code.yaml, languages.yamlWhich source files each code tab shows, and the list of implementations.
site/i18n/en.yaml, fa.yamlInterface strings (buttons, labels) per language.
site/layouts/The page templates. Rarely need editing.
site/assets/css, assets/jsLook, and the behaviour (language tabs, theme, mobile menu).
site/hugo.tomlConfiguration, including where the code tabs read the real source files from.

Build and preview

Install Hugo (extended edition, 0.158 or newer), then from site/:

hugo server            # live preview at http://localhost:1313/, English and /fa/
hugo --minify          # build the site into site/public/

Nothing generated is committed. A GitHub Actions workflow (.github/workflows/hugo.yml) builds the site on every push to main and publishes it to GitHub Pages (Settings, Pages, Source: GitHub Actions).

Add a page

  1. Create site/content/en/ch03-3-self-attention.html starting with: 
    ---
title: "3.3: A simple self-attention mechanism"
nav: 3.3 Self-attention
chapter: "3"
sections: ["3.3"]
order: 30
code: attn_self
---
<div class="aim"><b>Aim.</b> ...</div>
...
<!--code-->
  2. chapter is the chapter number as a string (or A for appendices, start and reference for the first and last groups); sections lists the book sections the page covers (["2.7", "2.8"] for two); order sorts pages inside a chapter. nav is the short name in the side menu.
  3. Put the comment <!--code--> where the Python / Go / Rust / C / Zig tabs should go, and name the entry in code: (defined in data/code.yaml, see below).
  4. Add the Persian page with the same file name in site/content/fa/.
  5. Run hugo server. The section flips from planned to ready on the roadmap by itself. Other markers you can use in a page body: <!--cards--> (chapter cards), <!--progress--> and <!--matrix--> (the roadmap tables).

Add an extra

An extra goes beyond the book. Use the same front matter, add extra: true, and leave sections out. It appears under its chapter, marked with a plus, and on the chapter page.

Add code for a chapter

  1. Write the same module in every language folder, using the same names (see the layout on the reference page). Match outputs across languages.
  2. In site/data/code.yaml add an entry listing the files each language tab shows, e.g. attn_self: {python: [attention/self_attention.py], go: [...], ...}. A language you leave out shows "Not implemented in this language yet". The site reads the files straight from the repository at build time, so the tabs never drift from the code. (If you add a new folder, mount it in hugo.toml.)
  3. Set the chapter's langs in data/chapters.yaml to the languages that now implement it. The language matrix on the roadmap updates.

Add a language

  1. Create Lang-version/ with the same layout and a README, and mount its source folder in hugo.toml.
  2. Add it to site/data/languages.yaml with the name of its syntax highlighter (a Chroma lexer). Code is highlighted at build time, no JavaScript.
  3. Add its files to each code.yaml entry and to the chapters' langs as it catches up.

Add a chapter

Chapters 5 to 7 and the appendices are already outlined in data/chapters.yaml as planned, each with a chapter-N.md stub. To refine one, edit its sections list; to write it, add pages as above. A brand-new chapter needs a block in chapters.yaml and a stub file in both languages.

Add a translation

The site is built in English and Persian. A translated page is a file with the same name in site/content/fa/. Copy the English page, translate title, nav and the text, and keep the other front-matter keys (chapter, sections, order, code, extra) identical. Keep code blocks, output blocks and the <!--code--> marker unchanged.

  • Chapter titles, summaries and section names come from data/chapters.yaml; buttons and labels from i18n/fa.yaml. A new language is one more block in hugo.toml, a new content/<lang>/ folder, an i18n/<lang>.yaml file and a title per language in chapters.yaml.
  • Hugo does not fall back to English for a page missing in another language: the page is simply absent there (and absent from its menu). Translate all pages of a chapter together.

Writing guidelines

  • Start every page with an Aim: what the reader will understand.
  • Explain in plain words first, then show code. Keep the book's section numbers in titles.
  • Real numbers from real runs beat invented ones. If you paste output, run the code first.
  • Own words only. Do not copy the book's text or figures.
  • End with exercises or "check yourself" questions, and hide answers in a <details class="qa"> block.
