Aim. See, with no trainable weights, how every token gets a context vector that blends in the other tokens.

The idea in one picture

When you read "journey" in "Your journey starts with one step", its meaning depends on the words around it. Self-attention gives each token a way to listen to the other tokens. Picture a mixing desk with six sliders, one per word. For each token the model sets the sliders (how much to listen to each word), and the output is the blend. The six slider settings are always positive and add up to 100%.

That blend is the context vector: the token's own embedding, enriched with information from all the other tokens.

Notation. xi is the embedding vector of token i. ωij (omega, read it as a "w") is the score of query token i against token j. αij is the attention weight after softmax. zi is the context vector of token i. For example ω21 compares "journey" with "Your", and α23 is how much "journey" listens to "starts". XT means the matrix X with rows and columns swapped.

Our sentence is already embedded as six 3-dimensional vectors (chapter 2 made these). Row 1 is "Your", row 2 is "journey", and so on.

x1 Your     [0.43, 0.15, 0.89]
x2 journey  [0.55, 0.87, 0.66]
x3 starts   [0.57, 0.85, 0.64]
x4 with     [0.22, 0.58, 0.33]
x5 one      [0.77, 0.25, 0.10]
x6 step     [0.05, 0.80, 0.55]

First, how do you measure "related"? The dot product

We need a number that says how much two vectors are alike. The dot product multiplies matching entries and adds them up. Geometrically it is big and positive when two vectors point the same way, zero at a right angle, and negative when they point apart.

Here, "related" just means "the embeddings are close". Nothing has been trained to know grammar, so a high score means similar vectors, not "grammatically linked".

Three steps, for one query (x2, "journey")

  1. Scores. Dot product of the query with every token: ω2j = x2 · xj. 
    scores = [0.9544, 1.4950, 1.4754, 0.8434, 0.7070, 1.0865]
  2. Weights. Normalise the scores so they are positive and sum to 1. Plain division by the sum works, but softmax is standard: it handles extreme values better and has friendlier gradients. 
    divide by sum: [0.1455, 0.2278, 0.2249, 0.1285, 0.1077, 0.1656]
softmax      : [0.1385, 0.2379, 0.2333, 0.1240, 0.1082, 0.1581]
  3. Context vector. Weighted sum of all token vectors, using those weights. 
    z2 = α21*x1 + α22*x2 + ... + α26*x6 = [0.4419, 0.6515, 0.5683]

Step 3 as a recipe

Each token contributes its weight times its vector. Adding the six rows column by column gives the context vector. You can see "journey" and "starts" supply most of it, while "with" and "one" add only a little.

Why softmax and not plain division?

Both give positive weights that sum to 1. Softmax uses exp, which grows faster than a straight line, so a bigger score gets a more-than-proportional share. With our small scores the two look similar. Multiply the scores by 5 (as a stand-in for larger embeddings) and softmax starts to pick winners, while plain division cannot change: it only depends on proportions.

Softmax in code subtracts the largest score first. The result is identical, but exp can no longer overflow on big numbers. Making softmax too sharp is a real problem later; the extra on scaling shows how it is fixed.

All tokens at once: three matrix operations

Stack the loop over all queries and it becomes matrix algebra. With X the 6x3 input matrix:

XT3×6

softmax6×6

X6×3
same vectors again

scores  = X x X^T                  (6 x 6)  every token against every token
weights = softmax(scores, row by row)          each row sums to 1
context = weights x X                (6 x 3)  one context vector per token

The first product is just all the dot products at once: entry (i, j) of X·XT is xi · xj, which is ωij. Here is the matrix of weights αij as a picture; darker means more attention.

What the picture tells you

  • The "journey" and "starts" columns are dark for almost every row. Their embeddings are long and nearly identical, so their dot product with everything is large. This is the length effect of the dot product.
  • The "with" column is pale for every row. Its vector is short (length 0.70 against 1.22 for "journey"), so it scores low with everyone.
  • The table is symmetric before softmax (ωij = ωji), because a token's vector is used both to ask and to be asked. Softmax normalises each row separately, which is why the weights are not symmetric.

Row 2 of the matrix result equals the vector we built step by step. That is the whole check. The matrix form is just the loop, done faster.

What is missing

Nothing here learns. The weights come straight from raw embedding similarity, and the same vector xi is used three ways: to ask, to be compared with, and to be mixed in. The next page splits these roles into a query, a key and a value, each made by a trainable matrix, so the model can learn what to look for. That also breaks the symmetry above: "journey" may care about "starts" more than "starts" cares about "journey".

Exercises

  1. Compute the context vector for "step" (row 6) by hand using the weights above, then check it against the code.
  2. Replace softmax by division by the row sum. Which tokens gain or lose weight, and why does softmax favour the larger scores?
  3. Which token has the highest weight for "journey"? Is it "journey" itself?
  4. Why is the "with" column pale for every row?
Answer to 3"journey" itself (0.2379), narrowly ahead of "starts" (0.2333), because a vector is always most similar to itself and "starts" has a very similar embedding.
Answer to 4The embedding of "with" is short (length about 0.70). A dot product scales with vector length, so it scores low against every query, and its weight stays small.
Why do the weights of one row always add up to 1?Softmax divides each exponentiated score by their sum, so the row is a set of shares of a whole. That makes the context vector a true weighted average of the token vectors.
