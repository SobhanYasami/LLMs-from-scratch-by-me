Aim. Understand the backward pass of the training loop one rule at a time, with small numbers, so the 200 lines of grad.* read as a list of simple facts.

The loss is a long chain of small functions: look up embeddings, normalise, multiply by matrices, softmax, and so on. The chain rule says: to know how the loss changes when an early number changes, multiply how each link of the chain changes. Backpropagation does that efficiently by going from the loss backwards, carrying along "how the loss changes with this layer's output" (call it dy) and turning it into "how it changes with the layer's input" (dx) and with its weights.

1. Loss and softmax

The loss at one position is -log p(target) where p is the softmax of the scores. Its gradient with respect to the scores is wonderfully simple:

d loss / d score_j  =  p_j - (1 if j is the target else 0)

Example with three scores [2.0, 1.0, 0.1] and the first one correct: softmax gives p = [0.659, 0.242, 0.099], the loss is -ln 0.659 = 0.417, and the gradient is [-0.341, 0.242, 0.099]. Read it: raise the correct score (negative gradient means "going up lowers the loss") and lower the others, the more probable a wrong one is, the harder. We divide by the number of positions N because the loss is a mean.

2. A linear layer: y = x W + b

WantedRuleIn words

Tiny case: x = [2, 3], W = [[1], [-1]], b = 0, so y = 2 - 3 = -1. If dy = 0.5: dW = [[2 x 0.5], [3 x 0.5]] = [[1.0], [1.5]] and dx = [0.5 x 1, 0.5 x -1] = [0.5, -0.5].

3. GELU

An elementwise function: dx = dy x gelu'(x), where gelu' is its slope. The program uses the formula derived from the tanh approximation of 4.3.

4. Shortcut: y = x + f(x)

Gradients add: dx = dy + (gradient through f). The first term is the gradient taking the shortcut, untouched. That is why shortcuts cure vanishing gradients (4.4): the backward pass has a path where nothing shrinks. In the code: add_into(dx, dx_mid), twice per block.

5. Layer norm

With xhat = (x - mean) / sqrt(var + eps) and y = scale * xhat + shift:

dscale = sum of dy * xhat       dshift = sum of dy
dxhat  = dy * scale
dx     = inv * ( dxhat - mean(dxhat) - xhat * mean(dxhat * xhat) )      inv = 1 / sqrt(var + eps)

The two subtracted terms exist because the mean and the variance of the row depend on every element of it: changing one input shifts them all, and the correction removes the part of the gradient that would only move the mean or the spread.

6. Attention

For each head, with P the attention weights (after softmax) and V the values, the forward pass was S = Q KT / sqrt(d), P = softmax(S), context = P V. Backwards:

dP = dcontext V^T          dV = P^T dcontext
dS = P * ( dP - rowsum(dP * P) )          (softmax backward)
dQ = dS K / sqrt(d)        dK = dS^T Q / sqrt(d)

Positions hidden by the causal mask have P = 0, so their dS is 0: the future gets no gradient, just as it gets no attention. The softmax rule has the same "minus the weighted average" shape as layer norm's.

7. Embeddings

A lookup has no arithmetic to undo: the gradient of a token's row is the sum of the gradients dx of every position where that token appeared. A token that is not in the batch gets zero gradient, so most rows of the 50,257-row table stay untouched in each step.

How the code is organised

  1. Forward with a cache: run every layer and keep the matrices the backward rules need (inputs, normalised values, attention weights, the pre-GELU values).
  2. Loss and dlogits (rule 1).
  3. Output head and final norm, then the blocks from last to first: feed forward (rules 2, 3, 2), shortcut, layer norm, attention (rules 2, 6, 2 three times), shortcut, layer norm.
  4. Embeddings (rule 7).

Gradients add into a model-shaped container; that is why the loop zeroes it before each step. And because the container is shaped like the model, the optimizer and the checkpoint code treat weights, gradients and optimizer state in exactly the same way.
