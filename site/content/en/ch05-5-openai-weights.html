Aim. Skip the expensive pretraining: load OpenAI's published GPT-2 weights into our model and watch it write real sentences.

Pretraining a GPT-2 costs tens of thousands of dollars in compute. OpenAI released the result, so we can start from there. The architecture is exactly the one we built in chapter 4, so loading the weights is a matter of putting each number in the right place.

Get the weights

One file, about 500 MB. It is ignored by git:

curl -L -o assets/gpt2/model.safetensors \
  https://huggingface.co/openai-community/gpt2/resolve/main/model.safetensors

The book downloads TensorFlow checkpoints and needs TensorFlow to read them. The same weights exist in the safetensors format, which is so plain that no library is needed:

BytesContent
first 8the length N of the header, as a little-endian integer
next Na JSON header that lists every tensor: its name, shape and where its numbers sit in the file
the restall the tensors as raw 32-bit floats

Our five languages each read it in about 30 lines. A header entry looks like "h.0.attn.c_attn.weight":{"dtype":"F32","shape":[768,2304],"data_offsets":[a,b]}.

Matching OpenAI's names to ours

Four differences have to be bridged:

OpenAIOurs
wte, wpetoken embedding, position embedding
h.i.attn.c_attn: one matrix [768, 2304] with query, key and value side by sidethree matrices W_query, W_key, W_value [768, 768]: split the columns in three
the query/key/value projections have biasesthe config option qkv_bias = True (off in our own models)
h.i.attn.c_proj, h.i.mlp.c_fc, h.i.mlp.c_projthe attention output projection and the two feed forward layers
h.i.ln_1, ln_2, ln_fnorm1, norm2 of block i and the final layer norm
no separate output matrixweight tying: the output head is the token embedding again, so we copy wte into it (transposed)

Matrices in the file are [in, out], like our own. (The book's PyTorch layers want [out, in], so its loader transposes; ours does not have to, except for the tied head.) If a shape does not fit, the loader stops with an error, which is how mistakes show up.

GPT-2 uses attention biases and the model has 163,037,184 parameters with them: 163,009,536 (chapter 4) plus 12 blocks x 3 x 768 = 27,648.

It speaks

Run it with the same sampling settings as the book (top-k 50, temperature 1.5) and with greedy decoding:

loaded GPT-2 small: 163,037,184 parameters (with the attention biases)
generated: 'Every effort moves you across mountains," she wrote in 1912.   So far, that hasn't worked. The country spent nearly 2.3'
greedy   : 'Every effort moves you forward.  The first step is to understand the importance of your work.  The second step is to understand the'
exercise 5.5: loss of the pretrained model on The Verdict (validation part, 2 batches of 2 x 64 tokens): 3.791
  • Real sentences, from the same code that wrote gibberish in chapter 4. All five languages print exactly this text. If one number were in the wrong place, the text would collapse into noise: that is the test that the loading is right.
  • Exercise 5.5: the pretrained model has a loss of 3.79 on text from The Verdict that it has never seen (our tiny model had 7). Perplexity: exp(3.79) = 44, as if choosing among 44 words at each step instead of 50,257.

It takes about 4 seconds in Python (torch has fast matrix code) and 20 to 60 seconds in the others (build Rust with --release and Zig with -Doptimize=ReleaseFast): 25 tokens, each a full pass over the growing text.

Exercises

  1. Generate with temperature 0.7 and top-k 20. Is the text more or less sensible than with 1.5 and 50?
  2. What happens to the text if you forget to copy the weights into the output head?
  3. Compute the loss of the pretrained model on the training part of the story too. Is it lower or higher than the validation part?
Answers1) More sensible and more repetitive. 2) The head stays at its random values, so the scores are random and the text is gibberish again. 3) Expect a similar number: GPT-2 never saw this story, so the training and validation parts are equally new to it.

Check yourself

Why did OpenAI's attention need qkv_bias = True?Their projections have biases; our own models leave them out, so we add the option to match the weights.
What is weight tying?Using the token embedding matrix as the output head too, so one set of numbers serves both.
How do we know the weights were loaded correctly?The model writes coherent text; a single misplaced tensor would give noise.
