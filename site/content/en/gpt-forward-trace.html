Aim. Walk the four tokens of "Hello, I am" through the real 124M model and write down the shape of every tensor, so the whole chapter fits in one table.

T = 4 tokens, D = 768, 12 heads of 64 numbers each, vocabulary 50,257. Every step below is a function from the previous tensor to the next.

StepWhat happensShape after
0token IDs [15496, 11, 314, 716][4]
1look up rows of the token embedding (50,257 x 768)[4, 768]
2add position embedding rows 0..3 (1,024 x 768)[4, 768]
transformer block, repeated 12 times
3layer norm 1[4, 768]
4multiply by W_query, W_key, W_value (768 x 768 each)3 x [4, 768]
5split into 12 heads of 64 columns12 x [4, 64]
6per head: scores = q x kT, mask the future, softmax12 x [4, 4]
7per head: weights x v, glue the heads back[4, 768]
8output projection (768 x 768) + bias, then add the block's input (shortcut)[4, 768]
9layer norm 2[4, 768]
10feed forward: expand to 3,072, GELU, shrink to 768[4, 3072] then [4, 768]
11add the input of this sub-layer (shortcut)[4, 768]
after the 12th block
12final layer norm[4, 768]
13output head (768 x 50,257)[4, 50257]
14take the last row, pick the biggest scoreone token ID

The only mixing between tokens is step 6: the 4 x 4 attention weights. Everything else treats each of the 4 rows separately.

Where the time goes

Almost all the work is matrix multiplication. Counting multiply-adds per token:

PartMultiply-adds per token
one block: query/key/value/out projections, 4 x 768 x 7682,359,296
one block: feed forward, 2 x 768 x 3,0724,718,592
12 blocks together84,934,656
output head, 768 x 50,25738,597,376
total (attention scores add a little more)about 123.5 million

So one forward pass over a 14-token text is about 1.7 billion multiply-adds, and generating six tokens without a KV cache repeats that six times with growing input. That is why the 124M demo takes seconds, while the tiny model takes milliseconds. Notice that the output head alone is almost a third of the work: it scores all 50,257 words at every position, although generation only needs the last one.

Try it

  1. Redo the table for the tiny model (D = 32, 4 heads, 2 blocks). What are the shapes of steps 5 and 6?
  2. How would the cost per token change if you doubled D? Which part of the table grows fastest?
Answers1) Step 5: 4 x [4, 8]; step 6: 4 x [4, 4]. 2) The block cost grows with D squared (both rows), so it quadruples; the output head only doubles.
