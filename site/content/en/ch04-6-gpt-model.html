Aim. Assemble the full GPT model, count its parameters, and understand where the "124 million" comes from.

Assembly

The model is the pipeline of 4.1 with the real parts plugged in: token embedding, position embedding, N transformer blocks, a final layer norm and a linear output head with no bias.

x = token_embedding[ids] + position_embedding[0..T-1]      [T, D]
for each block:  x = block(x)                              [T, D]
x = final_layer_norm(x)                                    [T, D]
logits = x @ output_head                                   [T, vocab]

The position table is read with 0, 1, ..., T-1 (chapter 2) and added to every token. The class is short because the transformer block carries the complexity.

How the weights are initialised

Every weight matrix is filled from the shared seeded generator as Normal(0, 0.02), in a fixed order: token embedding, position embedding, then for each block W_query, W_key, W_value, out projection, feed forward 1, feed forward 2, and finally the output head. Biases start at 0, layer-norm scales at 1, shifts at 0. Because the order is part of the recipe, every language ends up with the same model.

How many parameters?

tiny model: 3,242,240 parameters (arithmetic says 3,242,240)
GPT-2 small, no model built: 163,009,536 parameters
  minus the output head (weight tying in the original GPT-2): 124,412,160
  float32 size: 621.83 MB

The code counts the model by building it and also by arithmetic, and the two agree. For GPT-2 small the parts are:

The step-by-step derivation, including the 7,085,568 per block, is in the extra on parameter counting.

Why 163 million and not 124 million?

The original GPT-2 uses weight tying: the output head reuses the token embedding matrix (the embedding maps ID to vector, the head maps vector back to a score for each ID, so the two matrices have the same shape [50,257, 768]). Counting that matrix only once removes 38,597,376 parameters: 124,412,160, the famous "124M". Our model keeps them separate, which the book finds trains a little better, and so do modern LLMs. Chapter 6 loads OpenAI's weights and revisits tying.

Memory

Each parameter is a 32-bit float, 4 bytes: 163,009,536 x 4 bytes = 621.83 MB just for the weights of a "small" model.

Bigger models, same code

                           parameters    weight-tied  float32 MB
  gpt2-small              163,009,536    124,412,160      621.83
  gpt2-medium             406,212,608    354,749,440    1,549.58

This is book exercise 4.2: the bigger GPT-2 models differ only in configuration (emb 1024/1280/1600, layers 24/36/48, heads 16/20/25). The program computes them by arithmetic without building them; the XL model would take 6 GB.
