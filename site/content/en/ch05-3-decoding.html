Aim. Make the model's text less repetitive with temperature scaling and top-k sampling, and learn what each knob does to the probabilities.

Greedy decoding (chapter 4.7) always picks the most likely token. Run it twice on the same prompt and you get the same text, often a passage copied from the training data. To get variety, we draw the next token from the probabilities instead of taking the biggest one.

A nine-word example

Suppose the model must continue "every effort moves you" over a vocabulary of nine words and gives these scores:

next-token probabilities: [0.0609, 0.0016, 0.0001, 0.5721, 0.0034, 0.0001, 0.0001, 0.3576, 0.0040]
greedy pick: forward

0.06090.00160.00010.57210.00340.00010.00010.35760.0040

Greedy always says "forward". Sampling says "forward" 57% of the time, "toward" 36%, "closer" 6%, and, rarely, something odd.

Temperature: sharpen or flatten

Divide the scores by a number T before softmax:

  • T < 1 makes big scores bigger relative to the rest: the distribution gets peakier, behaviour approaches greedy.
  • T = 1 changes nothing.
  • T > 1 evens the scores out: the distribution gets flatter, more surprising words get a chance.

1,000 draws with the repo's generator (seed 123) show it:

temperature 1: P(pizza) = 0.0001  1000 draws: 51 x closer, 2 x every, 594 x forward, 3 x inches, 344 x toward, 6 x you
temperature 0.1: P(pizza) = 0.0000  1000 draws: 990 x forward, 10 x toward
temperature 5: P(pizza) = 0.0430  1000 draws: 155 x closer, 77 x every, 42 x effort, 247 x forward, 97 x inches, 41 x moves, 45 x pizza, 225 x toward, 71 x you
  • At T = 0.1 "forward" wins 990 times out of 1,000: almost greedy.
  • At T = 5 every word gets drawn, including "pizza" 45 times (probability 4.3%): "every effort moves you pizza".

(The book's torch counts differ because torch's sampler uses a different random stream; the proportions agree.) Exercise 5.1 asks for the probability of "pizza": no need to sample, just read it from the softmax. That is the faster and more accurate way: 0.0001, 0.0000 and 0.0430.

Top-k: only the best candidates

High temperature lets nonsense in. Top-k keeps only the k highest scores and sets the others to -inf, which softmax turns into probability exactly 0:

top-3 logits: [6.75, 6.28, 4.51] at positions [3, 7, 0]
after masking with -inf: ['4.51', '-inf', '-inf', '6.75', '-inf', '-inf', '-inf', '6.28', '-inf']
top-3 probabilities: [0.0615, 0.0000, 0.0000, 0.5775, 0.0000, 0.0000, 0.0000, 0.3610, 0.0000]

Only "closer", "forward" and "toward" can be drawn. "pizza" is gone for good. (The same -inf trick hid future tokens in chapter 3's causal attention.)

The generate function

Put together, one generation step is: take the last row of logits, optionally apply top-k, optionally divide by the temperature, softmax, draw (or take the argmax when the temperature is 0), append, repeat.

With the trained tiny model:

greedy   : 'Every effort moves you............,,,'
top-k 25, temperature 1.4: 'Every effort moves you it my't with he it him of that. you meI. me'
temperature 0 equals greedy: true

Greedy is stuck on punctuation. Sampling produces a varied (nonsense, but varied) mix of common words. Temperature 0 turns the randomness off, which is exercise 5.3.

How the draw works here

The book uses torch.multinomial. To make all five languages agree we draw our own way, inverse-CDF sampling: pick one uniform number u between 0 and 1, add up the probabilities in order, and stop at the first token where the running total passes u. A token with probability 0 can never be picked. The uniform numbers come from the same splitmix64 generator as everything else in this repo.

What does a temperature above 1 do to the probabilities?It flattens them, so unlikely tokens get drawn more often.
