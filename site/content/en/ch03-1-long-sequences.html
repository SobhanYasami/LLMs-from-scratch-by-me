Aim. Understand the problem attention solves, and what the four attention variants of this chapter are.

The problem: a single summary is not enough

Analogy. Read a long paragraph once, close the book, and translate it from memory. That is the encoder-decoder RNN. Attention is translating with the book open on the desk, glancing at the right sentence each time.

Translating a sentence word by word fails, because word order and grammar differ between languages. Before transformers, the standard fix was an encoder-decoder RNN. An RNN reads text one step at a time, updating a hidden state (its memory) at each step.

Encoderreads the whole input, squeezes it into one final hidden state
→
One hidden statethe only thing the decoder gets
→
Decoderwrites the translation word by word

The decoder cannot look back at the encoder's earlier states. Everything about a long sentence has to survive in that single vector, so context is lost over long distances.

This is the whole problem in miniature. The RNN has to carry keys = plural through seven updates, each of which also has to store the new words. Nothing forces it to keep the clue, and during training the learning signal that says "you should have kept it" has to travel back through the same seven steps, shrinking as it goes (the vanishing gradient problem). Attention gives are a direct line back to keys.

Sequential versus direct: how far apart are two words?

There is a second weakness, separate from the bottleneck. An RNN reads in order, and step t needs the result of step t-1. Information from token 1 reaches token 8 only by being handed down through every step between them.

RNN: a chain

Path between token 1 and token n is n-1 steps. Step t must wait for step t-1, so the positions of one sentence cannot be processed in parallel during training.

Attention: a table

Every pair of positions gets a score directly, so the path is 1 step. All the scores come from one matrix multiplication, which GPUs do very well. This is why transformers train so much faster.

The fix: let the decoder look back, selectively

In 2014 Bahdanau attention changed the decoder so that, at each output step, it can pick which input positions to read, giving some positions more attention weight than others. Three years later the transformer showed the RNN itself is not needed: use attention alone, applied by the sequence to itself.

Self-attention. Every position in a sequence looks at every position in the same sequence (including itself) to build a better representation of itself.

Note the order of events. Bahdanau attention (2014) fixed the bottleneck but still ran on an RNN, so it was still sequential. The transformer (2017) removed the RNN and fixed both problems.

What attention does not solve

"Attention fixes long sequences" is true, but it is not free and it is not magic. Keep these limits in mind, because later chapters run into each one.

  • It costs more as text grows. Every token is scored against every other token, so the work and memory grow with the square of the length. An RNN grows only linearly. This is why models have a fixed context window (1,024 tokens for the GPT-2 small model we load in chapter 5), and why long context is expensive.
  • Seeing is not using. The weights of a softmax add up to 1. When thousands of tokens compete, a single useful token can get a tiny share. In practice, models often use information in the middle of a very long input less reliably than at its start or end.
  • It has no sense of order. Attention compares positions as a set. Without the positional embeddings of chapter 2, "dog bites man" and "man bites dog" would look the same. The RNN got order for free from its step-by-step reading; the transformer must add it.
  • It does not make the model understand. Attention only makes the clue reachable. Whether the trained model learns to use it, for example to match keys with are, depends on training.

Check yourself

What is the bottleneck of an encoder-decoder RNN?The decoder only sees the encoder's final hidden state, so a long input has to be compressed into one vector.
Why is "keys ... are" hard for an RNN but easy for attention?The RNN has to keep "keys is plural" alive through every update between the two words, and the training signal has to travel back the same way. Attention links "are" directly to "keys" in one step.
Name two weaknesses of an RNN that the transformer fixes.The single-vector bottleneck (and long paths between far-apart words), and the sequential computation that prevents parallel training over positions.
Name one thing attention makes worse than an RNN.Cost on long inputs: work and memory grow with the square of the sequence length, so the context window is limited.
What does "self" in self-attention mean?The attention is computed between positions of the same sequence, not between two different sequences.
Which variant is the one GPT uses?Causal multi-head attention (3.5 and 3.6 combined).
