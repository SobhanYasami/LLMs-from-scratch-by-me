Extra: an embedding layer is a matrix multiply in disguise

extra

Aim. See that "look up row i" and "multiply a one-hot vector by a matrix" give the same answer, and why lookup is the one we use.

Section 2.7 says an embedding layer is a lookup table. Here is the other view, which explains why it can be trained like any other layer.

One-hot times matrix

Take a vocabulary of 6 tokens and embeddings of size 3. The weight matrix W has 6 rows and 3 columns. For token ID 3, build a one-hot vector: all zeros except a 1 at position 3.

one-hot(3) = [0, 0, 0, 1, 0, 0]

            | w00 w01 w02 |  row 0
            | w10 w11 w12 |  row 1
            | w20 w21 w22 |  row 2
[0 0 0 1 0 0] x | w30 w31 w32 |  row 3   -->  [w30 w31 w32]
            | w40 w41 w42 |  row 4
            | w50 w51 w52 |  row 5

Every other row is multiplied by 0 and vanishes. The result is exactly row 3. So an embedding layer equals a fully connected layer (no bias) fed with one-hot inputs.

Why use a lookup instead

One-hot + matmulLookup
Work per tokenvocab_size x dim multiplications, almost all by zerocopy dim numbers
Memorya vocab_size-long vector per tokenjust the ID
Same resultyes, identical numbers

With the real GPT-2 vocabulary of 50,257 tokens, the one-hot route would waste about 50,000 multiplications per token. In the code you have seen it directly: embedding_forward in C is a memcpy of one row.

Why it still matters

Because it is a matrix multiply, gradients flow back to the rows that were used, and only those rows get updated. That is how embeddings become meaningful during training (chapter 5) even though we only ever look them up.

Try it

  1. Use the 6x3 example in section 2.7. Write the one-hot vector for ID 5 and multiply by hand. Does it match the row?
  2. In your favourite of the five languages, implement the matmul version and check it equals the lookup on a small matrix.

Raschka's repo has a runnable version: 03_bonus_embedding-vs-matmul.
