Aim. Give every unique token a number (the vocabulary), then build a tokenizer with encode (text to IDs) and decode (IDs to text).

The vocabulary

Tokenize the whole training text, remove duplicates, sort alphabetically, number from 0. The story has 1,159 unique tokens.

('!', 0)  ('"', 1)  ("'", 2)  ...  ('Has', 49)  ('He', 50)
  • Sorted so the same corpus always gives the same IDs. Sets and maps have random order in all three languages.
  • For decoding we also need the inverse map, ID to token.

The tokenizer, V1

encodetext → tokens → IDs
·
decodeIDs → tokens → join → tidy punctuation

Try it on a sentence from the story:

[1, 58, 2, 872, 1013, 615, 541, 763, 5, 1155, 608, 5, 1, 69, 7, 39, 873, 1136, 773, 812, 7]
" It' s the last he painted, you know," Mrs. Gisburn said with pardonable pride.

When it breaks

Encode "Hello, do you like tea?" and V1 fails (KeyError: 'Hello' in Python, an error in Go, an Err in Rust, NULL plus a message in C, error.UnknownToken in Zig). "Hello" is not in the story, so it is not in the vocabulary. A closed vocabulary cannot handle new words. Next page patches that.
