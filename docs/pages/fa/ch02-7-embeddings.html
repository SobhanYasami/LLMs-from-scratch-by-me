2.7 امبدینگ توکن

لایهٔ امبدینگ ماتریس وزنی است با یک سطر برای هر مدخل واژگان و یک ستون برای هر بُعد. تبدیل یک شناسه یک جست‌وجوی سطر است.

vocab_size = 6, output_dim = 3
weight matrix (random at start):
 id 0  [ 0.3374, -0.1778, -0.1690]
 id 1  [ 0.9178,  1.5810,  1.3010]
 id 2  [ 1.2753, -0.2010, -0.1606]
 id 3  [-0.4015,  0.9666, -1.1481]   <- embedding of token 3
 id 4  [-1.1589,  0.3255, -0.6315]
 id 5  [-2.8400, -0.7849, -1.4096]

input_ids [2, 3, 5, 1]  ->  rows 2, 3, 5, 1  (a 4 x 3 matrix)
  • وزن‌ها تصادفی شروع می‌شوند و در آموزش با پس‌انتشار (فصل ۵) تنظیم می‌شوند. به همین دلیل لایه آموزش‌پذیر است و بردارها معنادار می‌شوند.
  • لایهٔ امبدینگ فقط نسخهٔ سریع‌تر کدگذاری one-hot ضرب در یک ماتریس است (پوشهٔ تکمیلی ۰۳ راشکا را ببینید).
  • با واژگان واقعی BPE: 50,257 سطر، و کتاب 256 بُعد می‌گیرد (GPT-3 از 12,288 استفاده می‌کند).

2.8 کدگذاری جایگاه کلمه‌ها

یک شناسه همیشه به همان بردار نگاشت می‌شود، هرجا که باشد. خودتوجهی هم نسبت به ترتیب کور است. پس اطلاعات جایگاه را اضافه می‌کنیم.

  • امبدینگ‌های جایگاه مطلق: یک بردار برای هر جایگاه (اول، دوم، ...). GPT از این‌ها استفاده می‌کند و در آموزش یاد گرفته می‌شوند.
  • نوع نسبی فاصلهٔ میان توکن‌ها را کد می‌کند و روی طول‌های دیده‌نشده بهتر تعمیم می‌دهد.
token ids          (8, 4)         batch of 8 windows, 4 tokens each
token embeddings   (8, 4, 256)    every ID became a 256-d vector
position embeddings (4, 256)      one vector per position 0..3
input embeddings   (8, 4, 256)    token + position  <- what the model reads

جدول جایگاه با 0, 1, ..., context_length - 1 جست‌وجو و به هر پنجرهٔ دسته اضافه می‌شود. متن بلندتر از طول زمینه باید بریده شود.
