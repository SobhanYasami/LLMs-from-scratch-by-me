Aim. Turn one long list of token IDs into training examples for next-token prediction.

BPE-encode the whole story: 5,145 tokens. Each example is a window of IDs (the input) and the same window shifted by one (the target). Every position in a window is a free question: "given these tokens, what comes next?"

x: [290, 4920, 2241, 287]
y:      [4920, 2241, 287, 257]

[290] ----> 4920
[290, 4920] ----> 2241
[290, 4920, 2241] ----> 287
[290, 4920, 2241, 287] ----> 257

as text:
 and ---->  established
 and established ---->  himself
 and established himself ---->  in
 and established himself in ---->  a

Left of the arrow is what the model sees, right is what it must predict. (The book first drops the first 50 tokens for a more interesting passage.)

Dataset and DataLoader

  • Dataset (GPTDatasetV1): holds every (input, target) window as tensors. Python extends torch's Dataset; Go and Rust use plain slices.
  • max_length: window size (the context). Tiny here (4); real training uses 256 or more.
  • stride: how far the window slides. stride=1 gives heavily overlapping windows; stride == max_length gives none.
  • DataLoader: groups windows into batches, optionally shuffled, optionally dropping a short last batch.
stride=1, batch_size=1:
[tensor([[  40,  367, 2885, 1464]]), tensor([[ 367, 2885, 1464, 1807]])]   first window
[tensor([[ 367, 2885, 1464, 1807]]), tensor([[2885, 1464, 1807, 3619]])]   second: shifted by one

stride=4, batch_size=8: inputs shape (8, 4), no overlap, no word skipped
The book uses stride = max_length for real batches: the whole text is used but nothing overlaps, since more overlap risks overfitting. Batch size is a trade-off: small uses less memory but gives noisier updates.
